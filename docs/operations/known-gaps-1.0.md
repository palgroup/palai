## 11. Findings from E26 (background execution) that 1.0 carries

Background execution's ceilings, and the shape of this section is unusual: **there are four rows and two of
them are the same fact seen from opposite ends.** `BGT-P1` is what a model does not get told; `BGT-P4` is what
survives a machine change. Both are consequences of decisions taken elsewhere — the first of `ShellRunner`
having one return value, the second of E24 T7's execution relay never having been shipped — rather than of
anything E26 chose. `BGT-P2` is the honest limit of process ownership on a host, and it is the one place in
this epic where the safe answer LEAVES US THE ORPHAN on purpose. `BGT-P3` is a convention wearing the shape of
a contract.

**No `BGT-P*` row is an RC-blocker.** Two of them (`BGT-P1`, `BGT-P4`) are named in the
`background-execution-0.1.0` bundle's own honest-ceiling paragraph, so a reader of the evidence meets them
before a reader of this file does. `BGT-P2`'s mitigation is a REFUSAL rather than a fix, and that is the
design rule rather than a shortfall: **not killing a stranger's process matters more than reaping our own.**

|---|---|---|---|---|---|
| `BGT-P1` | **THERE IS NO LIVE PROGRESS STREAM, SO A MODEL LEARNS NOTHING ABOUT A RUNNING BUILD UNLESS IT DECIDES TO READ.** E26 gives a background task a log file the model can read mid-flight, and that is a PULL. ## What is not in this table

  not-claimed list here would create a second source for it.

## How a row leaves this table

`closed-verified` requires evidence that **resolves** — a UAT case id or a test name that exists — and
`TestKnownGapsClosedRowsCiteRealEvidence` (`tests/docs/ops_docs_test.go`) fails a `closed-verified` row
whose evidence does not. A row cannot be closed by editing its decision column.
